# Working on Arca Verborum

Read [ONBOARDING.md](ONBOARDING.md) for the environment and build workflow,
[CONTEXT.md](CONTEXT.md) for terminology, and [docs/STATUS.md](docs/STATUS.md)
for the accepted data baseline. Parent workstation instructions also apply.

For “what could be next?”, coverage/source planning, or another expansion batch,
read [the coverage-planning workflow](docs/workflows/arca-coverage-planning/SKILL.md).
Use [docs/NEXT.md](docs/NEXT.md) as the active queue and
[the held-work register](docs/planning/HELD.md) for evidence needed to reopen a case.
Update these at batch closure. Dated reports and rankings are historical evidence;
check them against accepted output before proposing a task again.

The user's standing priorities are more languages, broader coverage and stronger
linguistic evidence, especially in the Americas and South America. Keep source
transcriptions, derived profiles, semantic judgments and source-specific cognacy
explicit. An intake source's spelling is not IPA merely because it tokenizes.

A planning request calls for recommendations and maintained documentation.
Execute data changes when the user asks to proceed; carry existing authorization
through the agreed batch. Choose implementation details autonomously within scope.
