# Independent adversarial review of colexification method

Scope: inspected implementation, tests, and the 2026-11-01 robustness specification; no production rebuild or data changes. This is a review of what the code estimates and its failure modes, not an independent audit of all source records. Confidence labels distinguish executable consequences from unmeasured empirical effects.

## Priority findings

1. **Conflicting local approvals do not fail closed (verified code-level bug; actual prevalence not measured).** `SemanticEligibility` assigns `self.local[av,pid] = target` for each `map`/`retain` row, without collecting or rejecting conflicting targets, and iterates multiple files via an unsorted glob (`src/arcaverborum/colexification_evidence.py:55-66`). Thus two approvals for the same variety/parameter with distinct targets yield whichever was encountered last, rather than the documented claim that conflicting parameter-level approvals remain unreviewed. The same overwrite issue applies to repeated exact form admissions at lines 67–69. This is a conditional bug, not proof that the current published graph contains such a conflict. A tiny fixture with two contradictory `concept_map.csv` rows and the same parameter should assert both candidate concepts remain unreviewed or construction fails, independent of row/file ordering. Collect target sets, distinguish native-record from parameter scope, and explicitly quarantine conflicts; audit the existing files before refreshing output.

2. **Resource survival does not mean two families survive deletion (verified, intentional current rule; interpretation risk).** `summarize` requires two families *before* deletion and positive remaining mass (`colexification_evidence.py:113-127`). The existing test explicitly verifies that `{f1:{A:1}, f2:{B:1}}` obtains weight 1 despite `families_without_one_block_min == 1` (`tests/test_colexification_evidence.py:12-17`). Thus a backbone edge can rest on a single remaining family after deletion of either block; two resource blocks can simply be two disjoint families. This matches the literal specification, but the name “replicated backbone” can invite a stronger interpretation. Display surviving family count alongside weight and state the criterion precisely. If the scientific claim requires genealogical replication under deletion, compare a stricter `min_families >= 2` sensitivity graph rather than silently changing the estimand.

3. **Projection is highly sensitive to dictionary granularity and incomplete concept inventories (mathematical consequence; impact unmeasured).** Mass is `2/[k(k−1)]` using *all* reported concepts in the identity before semantic gating (`colexification.py:358-363`, `colexification_evidence.py:138-145`). Adding a third, unreviewed or incompatible sense to an otherwise unchanged two-sense identity reduces its eligible pair mass from 1 to 1/3. A 64-sense group contributes 1/2016 per pair, while 65 is quarantined entirely (`colexification.py:363-374`). Conversely a narrowly sampled dictionary may give the same association weight 1. The maximum across family/resource witnesses then selects the smallest observed group (`colexification_evidence.py:138-145`), so supplementary sparse evidence can increase support even if a more complete source reveals a broad lexical item. Unit total group mass is defensible for clique dependence, but is not an unbiased frequency, probability, or normalized family prevalence. Add paired fixtures for k=2, 3 and 64/65, including an unreviewed third sense, and report changes under alternative per-node and ungated/group-size conventions. Report quarantine counts and affected concepts, not merely the cutoff.

4. **Family maxima and resource deletion do not establish independent replications (high confidence).** A family contributes its largest source/lect/group value; this ignores number and diversity of witnesses and selects the strongest value (`colexification_evidence.py:109-120`). The resource registry explicitly falls back to source namespace for unlisted sources (`colexification_evidence.py:130-135`), so derivatives with different unregistered namespaces may count as separate blocks; conversely a compilation containing independent dictionaries can be treated as one. Shared inheritance and areal diffusion remain, and distinct blocks are not independent original lexica. A stable edge can reflect one inherited innovation copied across varieties, or a shared compilation reproduced in unregistered resources. Trace lineage and original dictionary provenance for high-weight edges; run block-registry merge/split and family/subfamily/area sensitivity analyses. Do not describe `R` as calibrated lower confidence bound or independent replication.

5. **Semantic eligibility is asymmetric and review scope is narrow (high confidence; error rate unknown).** Only `transcription_source == 'wiktionary'` receives the headword review gate; every other source is automatically `source_mapping` (`colexification_evidence.py:71-83`), including differently named Wiktionary editions unless their rows actually carry that exact source value. Check source values before asserting their treatment. Controlled mappings may still have translation polysemy, incorrect English glosses, or mismatched concept granularity; no universal precision comparison follows from the gate. The 54 reviewed senses and representative-witness queue are targeted, not a random validation sample; one representative per identity/pair can hide other defective source records (`colexification.py:381-392`). Audit stratified random records by source, family and semantic field, blind to edge importance, including negative/unmapped senses and non-English source labels. Publish denominators and uncertainty; preserve local native sense and evidence. For collisions, test local parameter-level approvals as well as the shared rule: only the shared-rule path checks ambiguous names (`colexification_evidence.py:38-53`).

6. **Comparable is an observation opportunity, not a clean negative (high confidence).** `pair_status` requires compatible records within a single source/member/basis scope; `opportunities` calls a comparable variety with no identity `no_shared_form_observed` (`colexification.py:411-449`). A dictionary can have incomplete synonym coverage, both lexical items can be loans, register/stage may differ, and missing pronunciation or a false concept mapping can produce apparent nonidentity. Conversely sources across scopes cannot jointly establish a positive or a same-scope opportunity. Family fractions in `colexification_communities.py:291-303` combine raw positive family counts with comparable family counts; they do not correct uneven within-family or concept sampling and should not be read as cross-language prevalence. Test a partially sampled synonym, distinct source scopes, and a language with positive and negative lects. Label comparisons sampled/no shared form, with coverage and scope shown; use matched common concept inventories and transparent sampling models for prevalence claims.

7. **Community stability is conditional, not global certainty (high confidence).** Agreement compares only shared eligible nodes (`colexification_communities.py:95-108`), and bootstrap coassignment counts only when both nodes receive a partition (`:255-268`); a high conditional frequency can coexist with frequent disappearance. Family resampling selects from all known corpus families, including families without relevant witnesses, and each replicate fixes the clustering seed (`:255-263`); this is a corpus-family perturbation, not a calibrated sampling distribution. Show included/total replicates as well as coassignment, node and edge retention and common-node counts next to every ARI; compare intersections and union-aware missingness separately. The reported raw and Leiden disagreements already show model sensitivity; no seed medoid or algorithmic regularization establishes semantic categories.

8. **CLICS agreement is descriptive, not validation or a fair leaderboard (high confidence).** The comparison restricts the crosswalk to unique active Concepticon IDs (`colexification_comparison.py:71-77`) and reports overlap/Jaccard (`:80-82`), with direct CLICS4 forms separated from derived/shared-native forms (`:245-258`). Unique-ID filtering changes the domain; it does not ensure a shared sense or identical treatment of forms. Different inventories, sampling, source overlap, source scopes, concept mappings and release definitions create both false disagreements and non-independent agreements. Language-level matching can also conflate distinct lects/stages. Cite overlap on the matched concept, language, scope and direct-form subset together with exclusions and coverage; inspect disagreements against originals, and never treat CLICS absence as a false positive or agreement as independent confirmation. The CLICS³ paper describes the heterogeneous database and its network construction: https://doi.org/10.1038/s41597-019-0341-x ; CLICS⁴ provides its own documented construction: https://aclanthology.org/2025.iwcs-main.1/ .

## Prioritized verification and remedies

First fix conflict handling and audit current decisions, including ambiguous local IDs, before any new analytical publication. Next add the small synthetic tests above and a two-block/two-family counterexample to user-facing interpretation checks. Then quantify node/edge retention, source and family sensitivity, group-size and quarantine effects, and build a stratified semantic audit with independently adjudicated source evidence. Finally explore a null model preserving appropriate source inventories and sampling constraints; do not call the current cutoff significant. Projection alternatives address different estimands, as the bipartite projection literature emphasizes (Newman, https://doi.org/10.1103/PhysRevE.64.016132 ; validated projections, https://doi.org/10.1371/journal.pone.0244363 ). No claim here establishes that any alternative is universally superior.

## Follow-up bounded fixtures: local collisions and holds

A temporary-root fixture with two `parameters_raw.csv` rows sharing `wikt_collision` but bearing different `Name` values, plus a local `concept_map.csv` map to `c1`, returned `reviewed_dictionary_sense` for that parameter. No shared override file was present. The ambiguity check is confined to parameter IDs selected by the shared override file (`colexification_evidence.py:38-53`); local parameter approvals are loaded independently (`:55-66`). Thus a local parameter-level approval can validate an ambiguous ID without native-record discrimination. This is a verified API behavior; whether a currently used local approval intersects an actual collision was not determined. Extend the collision test to local approvals and require a record-scoped guard or fail closed on ambiguous names.

A second fixture added a `core_review.csv` row marking that same parameter `needs_review` alongside its positive local mapping. The gate still returned `reviewed_dictionary_sense`: `needs_review` is ignored while the positive mapping is retained (`:60-66`, `:79-82`). A shared positive mapping likewise has no hold check. Whether a local provisional hold should override a separately reviewed, potentially broader shared approval is a policy decision; current behavior does not enforce such precedence. A bounded scan found zero local parameter keys containing both positive and `needs_review` decisions and zero `needs_review` entries whose parameter also has a shared `map` override, so these fixtures do not establish present production impact. Add explicit precedence and scope tests, with hold reason and target preserved, before relying on a hold to suppress another approval.
